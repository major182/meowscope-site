一つひとつの入力値と期待する結果は、テストのコードに書く（コードが正）。

---

## 1. テストの区分

このサイトは、組み立てのときに HTML を書き出すだけで、動く処理（サーバー・スクリプト）を持たない。そのため、**出来上がりの HTML（`dist`）を確かめるテスト**を中心にする。

| 区分 | 何を確かめるか | 使う道具 |
|---|---|---|
| 単体テスト（UT） | 出来上がりの HTML の1ページずつ：決まり（言語・幅・スクリプトなし）とサイトの中のリンク | Node.js の標準のテストの仕組み（node:test）。`tests/site.test.ts` |
| 結合テスト（IT） | 公開した後のサイト：URL が開くこと、HTTPS、ドメイン | 手で確かめる（公開の作業のときに 6章の手順で行い、結果を書く） |
| 静的なチェック | 整形・型 | Prettier、`astro check` |

## 2. 観点の出し方

- 単体：要件の決まり（BR・NF）を、すべてのページに同じように当てはめる。ページが増えても、テストを書き足さずに対象が増える作りにする
- 結合：要件の受け入れ基準（AC-01〜04）

## 3. テストの名前の付け方

`UT-<番号> <ページのファイル>：<確かめること>（<要件 ID>）`

## 4. 観点表

| テスト ID | 区分 | 要件 ID | 観点 |
|---|---|---|---|
| UT-01 | 単体 | - | HTML のページが1つ以上ある（組み立てを忘れて、何も確かめずに通るのを防ぐ） |
| UT-02 | 単体 | NF-UX-02 | すべてのページが `lang="ja"` |
| UT-03 | 単体 | NF-UX-01 | すべてのページに、スマートフォンの幅に合わせる設定（viewport）がある |
| UT-04 | 単体 | NF-SC-02 | すべてのページに `<script>` がない |
| UT-05 | 単体 | NF-MT-01 | すべてのページの、サイトの中のリンク（`/` で始まる href・src）が、出来上がりのファイルを指している。外のリンクとメールのリンクは確かめない |

## 5. カバレッジ

テストの対象は出来上がりの HTML で、テストで動かすアプリのコードがないため、カバレッジは計測しない。代わりに、テストがすべてのページを対象にすること（UT-01〜05 が `dist` の HTML をすべて集めて確かめること）で、確かめ漏れを防ぐ。

## 6. 実行の方法

```powershell
npm run check   # 整形・型・組み立て・テスト。CI も同じコマンドを動かす
```
